# Agent Dashboard — дизайн

Дата: 2026-10-30 · Статус: согласован 2026-10-30 · Макеты: [`agent-dashboard.pen`](../../../agent-dashboard.pen)

Пометки: «решено» — так сказал или согласовал пользователь; «моё решение» — выбор автора документа, его можно оспорить.

## Зачем

На маке пользователя два десятка git-репозиториев и столько же worktree: под каждый тикет PyME заводится отдельный worktree, агенты Claude создают свои. В них постоянно что-то запущено: сессии Claude Code со своими MCP-серверами, dev-серверы, демоны, собранные из проекта приложения. Диск и память заканчиваются, и пользователь каждый день чистит ноут вручную: смотрит, какие worktree остались, какие docker-образы и кеши накопились, решает, что уже не нужно, и удаляет.

Приложение заменяет эти раскопки. В одном окне видно, что каждый проект занимает на диске и в памяти и что в нём запущено, а ежедневная уборка занимает секунды.

Основной пользователь — владелец этого мака: MacBook Pro M4 Pro, 24 ГБ памяти, 460 ГБ диска, macOS 26.5. Приложением смогут пользоваться и другие люди со своими хостингами и папками, поэтому ничего из этого окружения в нём не зашито (решено: «gitlab может быть у другого пользователя на другом адресе»; что приложение будут ставить другие люди — моё прочтение этих слов).

## Как выглядит успех

Открыл приложение и за минуту нашёл самое тяжёлое и явно лишнее: worktree со смёрженным MR, забытый dev-сервер или сессию агента, неиспользуемый образ. Удалил, не переключаясь между терминалом, Finder и Docker Desktop (решено).

## Цели

1. Найти все git-репозитории на маке и показать их worktree со статусом: ветка, синхронизация с remote, незакоммиченные изменения, stash, статус MR или PR (решено).
2. Показать процессы, которые работают в папках проектов или были оттуда запущены, с памятью, портами и временем работы (решено).
3. Показывать, сколько места освободится при удалении, а не сколько весит папка.
4. Сделать ежедневную уборку делом пары кликов: worktree со смёрженным MR или PR, сборки, кеши, docker.
5. Показать тяжёлое вне проектов: кеши пакетных менеджеров, Xcode, виртуалку Docker.

## Не цели

- Другие ОС: только macOS (решено).
- Git-клиент: коммиты, диффы, управление ветками. Исключение — удаление локальной ветки вместе с worktree.
- Замена Activity Monitor: показываем процессы, которые относятся к проектам, и общую сводку.
- Чистка кешей обычных приложений (Spotify, LM Studio, данные Claude): они входят в сумму как «Other», но не чистятся (моё решение).
- Фоновая работа в первой версии: без иконки в меню-баре, автозапуска и уведомлений (моё решение).
- App Store.

## Анти-цели: провал, даже если всё работает

- Приложение удалило что-то с несохранённой работой: изменённые или неотслеживаемые файлы, коммиты, которых нет на remote, stash (решено).
- Приложение само ест столько же ресурсов, сколько то, за чем следит (решено).
- Цифры врут: показываем «весит 48 ГБ», а удаление освобождает 1 ГБ.

## Ограничения

- Нативное приложение, не Electron и не Tauri (решено). Swift 6 и SwiftUI, только macOS 26 и новее (моё решение после ответа «только на маке»; на маке уже 26.5, есть Xcode 26.6 и Swift 6.3).
- Без песочницы: приложению нужно читать чужие процессы, обходить файловую систему и запускать `git`, `docker`, `colima` и другие CLI. Поэтому не App Store.
- Распространение как у minuta: подпись Developer ID, нотаризация, обновления через Sparkle из GitHub Releases (моё решение по образцу minuta).
- Лёгкость: в простое CPU почти не используется, тяжёлые сканы диска идут в фоне и кешируются.
- Работает без сети: статус MR и PR тогда становится «неизвестно».
- Поиск по всему диску вызовет системные запросы доступа к Desktop, Documents, Downloads и подключённым дискам. Приложение заранее объясняет, зачем они, и работает с тем, что разрешили. Full Disk Access не требуется (моё решение).

## Экраны

Макеты одобрены пользователем: `agent-dashboard.pen`, фреймы «Projects — light/dark», «Processes — light», «Caches and Docker — light», «Remove sheet — light». Интерфейс на английском (моё решение). На макетах шрифт Inter и иконки lucide, в приложении — системный шрифт и SF Symbols. Статусы MR, порт :4200 и часть цифр на макетах условные.

Окно в стиле macOS 26: плавающий сайдбар, тулбар с кнопками-капсулами, светлая и тёмная тема. Обычное окно, не приложение в меню-баре (моё решение).

**Первый запуск** (на макетах нет). Объяснение системных запросов доступа, затем скан в фоне с прогрессом. Учётки GitHub и GitLab подключаются в Settings → Accounts (моё решение).

**Сайдбар.** Разделы Projects, Ready to remove (со счётчиком), Processes, Caches and Docker. Ниже список репозиториев с числом worktree, внизу — свободное место на диске.

**Projects.**
- Сверху блок «Ready to remove»: worktree, готовые к удалению (правила ниже), сколько освободит каждый, кнопка Remove на строке и «Remove N…» на весь блок. Если в worktree что-то запущено, кнопка называется «Stop and remove…».
- Ниже дерево: репозиторий, под ним его worktree. Колонки: Name (с веткой и ahead/behind), MR / PR, State, Running, Real size. Фильтр All / Running / Needs attention.
- Справа инспектор выбранной строки: путь; кнопки Terminal, Finder, Open MR/PR; git (upstream, изменения, последний коммит, MR или PR); запущенные процессы с памятью; сколько места освободится из скольких занятых и почему (клоны pnpm); кнопка «Remove worktree…».

**Processes.** Полоса памяти по проектам и таблица процессов, сгруппированных по проектам: Process, Kind, PID, Port, Uptime, Memory, кнопка остановки. Сессии агентов, которые работают дольше суток, подсвечены.

**Caches and Docker.** Сколько всего занято вне проектов и полоса по категориям. Docker: статус VM, размер её диска, кнопка «Start and inspect». Сборки внутри проектов, кеши пакетов, Xcode — у каждой строки кнопка очистки.

**Remove sheet.** Подтверждение удаления: список worktree, галка «Also delete the local branches» (включена по умолчанию), галка «Don't ask again for merged, pushed worktrees», строка о том, что игнорируемые git файлы, например `tmp/`, удаляются вместе с папкой, итог «Frees X GB», кнопки Cancel и Remove.

## Данные и правила

### Где искать проекты

- По всему загрузочному диску (решено). Пропускаем системные папки (`/System`, `/Library`, `/usr`, `/opt/homebrew`, `/Applications`, `~/Library`, Корзина), служебные папки инструментов (`~/.cargo`, `~/.rustup`, `~/.npm`, `~/.cache`, `~/.bun`, `~/.claude/plugins`, `~/.codex` и подобные), `node_modules` и папки сборки. Список исключений редактируется в Settings, любой репозиторий можно скрыть из контекстного меню. Подключённые диски по умолчанию не сканируются, их можно включить (моё решение).
- Первый скан идёт в фоне с низким приоритетом, результат кешируется. Дальше новые и удалённые репозитории ловим через FSEvents.

### Проекты и worktree

- Проект — репозиторий с каталогом `.git`. Репозитории внутри служебных папок другого проекта (`tmp/`, `build/`, `.build/`, `DerivedData/`, `node_modules/`, `target/`) — не отдельные проекты, а часть родителя. Примеры: `dashboard/tmp/protos` есть в каждом worktree dashboard, SwiftPM checkouts лежат внутри minuta.
- Worktree берём из `git worktree list --porcelain` каждого репозитория, где бы они ни лежали: `~/Development/dashboard-worktrees/…`, `expense-tracker/.claude/worktrees/agent-…`.
- Основной worktree (сам репозиторий) показывается строкой-родителем и через приложение не удаляется.

### Статус MR и PR

- GitHub и GitLab, включая собственные инсталляции GitLab на любом адресе (решено). Хост берём из `origin`, MR или PR ищем по исходной ветке. Тип хостинга для незнакомого адреса приложение определяет само, а если не вышло — его указывают в Settings.
- Учётки — в Settings → Accounts: для каждого хоста свой токен в Keychain. Если на маке уже залогинены `gh` или `glab`, их авторизацию можно переиспользовать (моё решение).
- Состояния: open, draft, merged, closed, нет MR/PR. У репозиториев без remote, на неподдерживаемом хостинге или без учётки статус «неизвестно».
- MR мёржатся со squash, поэтому `git branch --merged` бесполезен: признак слияния берём только из API хостинга.
- Обновление при открытии приложения и по кнопке Fetch в тулбаре. Она же делает `git fetch --prune` по всем репозиториям.

### Реальный размер

- Real size — сколько байт освободится при удалении: сумма `ATTR_CMNEXT_PRIVATESIZE` (`getattrlist` с опцией `FSOPT_ATTR_CMN_EXTENDED`) по обычным файлам. Видимый размер, как у `du`, показываем только в инспекторе для сравнения.
- Проверено на этом маке: `node_modules` одного worktree dashboard — 2,78 ГБ видимых и 0,03 ГБ освобождаемых, потому что pnpm на APFS клонирует файлы из своего хранилища.
- Скан дорогой, около 62 тыс. файлов на один `node_modules`. Он идёт в фоне, результат кешируется и пересчитывается по изменениям (FSEvents).

### Процессы

- Процесс относится к самому глубокому worktree, в котором находится одно из (по порядку): его текущая папка; текущая папка ближайшего предка; путь к исполняемому файлу или аргументы командной строки. Последнее ловит собранные приложения: Minuta.app из DerivedData, meetily.app из `target/` (решено: «процессы в папках проектов или запущенные из них»).
- Только процессы текущего пользователя. Память считаем как Activity Monitor (`phys_footprint` из `proc_pid_rusage`). Порты — слушающие TCP-сокеты процесса.
- Сессия Claude Code показывается одной строкой: процесс `claude` и его дочерние MCP-серверы (у пользователя по 5–6 на сессию). Сессии из приложения Claude запускаются через хелпер `disclaimer` внутри Claude.app, CLI-сессии — командой `claude` из шелла.
- Виды: Agent session (Claude Code и Codex — моё решение), Dev server (слушает порт), Daemon (родитель — launchd), Built here (исполняемый файл внутри проекта), Shell, Other.
- Действия: остановить процесс, сессию целиком или всё в проекте.
- Обновление раз в несколько секунд, пока окно видно; когда окно скрыто — пауза.

### Docker

- Docker берём из текущего docker context: colima, Docker Desktop или OrbStack (моё решение). Для этих рантаймов всегда показываем статус и размер диска VM на хосте, даже когда VM выключена. У этого пользователя — colima: профиль `default`, сейчас выключен, диск VM занимает 20,5 ГБ из выделенных 100.
- Образы, контейнеры и тома видны, только пока VM запущена. Кнопка «Start and inspect» запускает её. Контейнеры привязываем к проектам по метке `com.docker.compose.project.working_dir`.
- Удаляем только неиспользуемые образы и остановленные контейнеры, с подтверждением.

### Кеши и сборки

- Известный список кешей, у каждого своя безопасная команда очистки: хранилище pnpm (`pnpm store prune`), Homebrew, npm, Go, Playwright, CocoaPods, Xcode DerivedData, недоступные симуляторы. Точные команды выбирает строитель.
- Сборки внутри проектов (`target/`, `build/`, `dist/` и т. п.) чистим, только если папка в `.gitignore` и в ней нет отслеживаемых файлов.

### Безопасность удаления

- Несохранённая работа в worktree — это любое из: изменённые или неотслеживаемые файлы; stash-записи, сделанные на его ветке; коммиты, которых нет на remote. Для ветки с upstream это «ahead > 0». Для ветки со смёрженным MR или PR, чья remote-ветка уже удалена, — локальный HEAD не совпадает с head SHA этого MR/PR и не является его предком. Для ветки без upstream и без MR/PR все её коммиты, которых нет ни в одной remote-ветке, считаются несохранёнными.
- Игнорируемые git файлы несохранённой работой не считаются и удаляются вместе с worktree, без архива: папки тикета в `tmp/`, клон protos, логи, `.certs`, `.claude/settings.local.json` (решено: «удалять, а не архивировать»).
- «Ready to remove» = MR или PR смёржен и нет несохранённой работы. Если в worktree что-то запущено, удаление идёт через «Stop and remove…». Worktree со статусом «неизвестно» в этот блок не попадают; их можно удалить вручную из инспектора, если нет несохранённой работы (моё решение).
- Worktree с несохранённой работой из приложения не удаляется: действие недоступно, причина видна оранжевой меткой в колонке State.
- Удаление: `git worktree remove` без `--force`, затем, если стоит галка, `git branch -D` для локальной ветки. Папки удаляются сразу, не в Корзину (моё решение). Отменить нельзя, это сказано в окне подтверждения.
- Каждое удаление и каждая очистка — через подтверждение. Для смёрженных запушенных worktree подтверждение можно отключить галкой «Don't ask again».
- Worktree, заблокированные через `git worktree lock` (так Claude Code помечает worktree своих сессий: `locked claude session <name> (pid N …)`), показываются с меткой Locked и причиной. Если процесс из причины блокировки уже не работает, блокировка считается устаревшей: приложение снимает её (`git worktree unlock`) и удаляет worktree по общим правилам. Если процесс работает, «Stop and remove…» сначала останавливает его. Сессия при этом остаётся в списке приложения Claude и указывает на удалённую папку (моё решение).

### Поведение мак-приложения

Меню со всеми командами и шорткатами (обновить, fetch, удалить, показать инспектор, Settings ⌘,), контекстные меню на строках, полная навигация с клавиатуры, светлая и тёмная тема, учёт настроек Reduce Motion и Reduce Transparency.
